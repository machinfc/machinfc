## From physics to HPC

I started out as a physicist in Havana. My first serious computing problem was parallelizing
Monte Carlo simulations of light transport in biological tissue on GPUs — that's where I learned
that the distance between a model and an answer is measured in FLOPs.

That work brought me to a Ph.D. in Engineering & Materials Science at **UASLP (Mexico)**, where I
spent five years between the lab and the terminal: designing granular-impact experiments, building
the acquisition-to-analysis software that ran them, and turning the data into predictive models and
open-source tools. The results are published in *Physical Review E* and *Granular Matter*.

Now I'm following that trajectory to where it has always pointed: **high-performance computing as a
software engineering discipline** — performance-critical C++, GPU acceleration, parallel numerics,
and the cloud infrastructure to run it at scale.

## What I'm building

**granimpact** *(in progress — repo coming soon)* — High-performance reimplementation of my
doctoral granular-dynamics simulations in modern C++17: CUDA kernels, CMake build system, Google Test
unit suite, and GitHub Actions CI running on AWS EC2. My proof-of-work for the transition from
research code to production-grade HPC software.

**[craterslab](https://github.com/gvieralopez/craterslab)** — Open-source Python library (PyPI, Sphinx
docs, CI) for automated morphological analysis of impact craters from 3D depth maps. Developed during
my Ph.D.; the software behind my *Granular Matter* 2024 paper.
